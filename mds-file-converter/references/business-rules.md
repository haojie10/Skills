# 业务规则

## Rule 1: 产品分类（留空）
- A 列分类默认保持为空。
- 除非用户有特殊指令，否则在转化过程中不需要匹配或填写产品分类。

## Rule 2: 供应商编号
- BA 列默认留空
- 若用户明确指定供应商名称，按指定值填入

## Rule 3: 品牌统一
- 全局统一填入 `Howstoday`
- 填入 BB 列

## Rule 4: 标题生成（电商风格）
- O 列：中文标题，约 20 字左右，模仿主流购物网站（如淘宝/京东）的产品标题命名风格
  - 示例：「食品级硅胶厨具套装耐高温不粘锅专用炒菜铲勺全套家用烹饪工具组合」
  - **强制要求**：O 列必须是纯中文（可包含阿拉伯数字），绝对不能包含任何英文单词。
- P 列：英文标题，Amazon 风格
  - 示例：`Food Grade Silicone Kitchen Utensil Set Heat Resistant Non-Stick Cookware Cooking Tools`
  - **强制要求**：P 列必须是纯英文（可包含阿拉伯数字），绝对不能包含任何中文字符。
- **禁止在标题中包含任何品牌名称（如 Howstoday）或供应商型号/编号**。
- **标题中禁止出现以下内容**（合规脚本会自动检测）：
  - 供应商型号（如 `BH-HY-001`、`GSPC-003`、`YF100524` 等）
  - 电气参数（如 `5.5V`、`0.2W`、`300mah`、`1.2V` 等）
  - 精确重量（如 `175g`、`0.11kgs` 等）
  - 精确尺寸中的单位（如 `120mm*130mm`）
  - LED/SMD 型号规格（如 `16*2835SMD`）
- **合规示例 (Good)**：`太阳能户外火焰庭院灯防水草坪景观装饰照明地插灯`
- **违规示例 (Bad)**：`BH-HY-001庭院景观175g装饰灯` / `5.5V单晶太阳能板装饰灯`

## Rule 5: 图片分类与放置
- E 列：产品主图（系列代表图）
- F-H 列：三视图（多角度拍摄图）
- I-K 列：尺寸图（带标注）
- L-N 列：场景图（渲染/应用图）
- AL 列：SKU 图（默认使用主图）

## Rule 6: 卖点格式化（三级优先级）
- **格式要求（严格遵守，必须包含冒号）**：
  - 中文卖点格式必须为：`卖点名称：卖点说明`（例如 `食品级材质：采用食品级硅胶，耐高温230度`）
  - 英文卖点格式必须为：`Feature Name: Feature description`（例如 `Food Grade Material: Made of food grade silicone, heat resistant up to 230C`）
  - **卖点名称必须是具体的、描述性的词组**，不可使用通用占位符
  - **合规的卖点名称示例**：`智能光控`、`防水等级`、`材质工艺`、`便携设计`、`续航能力`
  - **违规的卖点名称示例**：`亮点`、`卖点一`、`卖点二`、`Point 1`、`Point 2`、`Feature 1`
- **卖点中禁止包含供应商型号**（如 `BH-HY-001`），型号不是卖点的一部分
- **列排布规则（严格遵守）**：卖点按中英文交替配对排列：
  - Q = 卖点1（中文），R = 卖点1（英文）
  - S = 卖点2（中文），T = 卖点2（英文）
  - U = 卖点3（中文），V = 卖点3（英文）
  - W/X、Y/Z、AA/AB ... 以此类推，至多 10 对（到 AI/AJ）
- **最终输出**：至少 3 条中英双语卖点对，至多 10 条。**每个产品都必须有卖点，不可遗漏。**
- **优先级1**：源文件中是否有明确的卖点/特点描述（如 Features / Highlights / Remark 等字段）
  - 有 → 直接提取，由 LLM 润色为中英双语格式
- **优先级2**：源文件中的 Description / 材质 / 结构信息
  - 有 → 由 LLM 结合这些信息提炼卖点
- **优先级3**：产品图片理解
  - 以上信息不足以凑齐 3 条时，LLM 通过看图生成/补充卖点
- **优先级4（兜底）**：若以上信息均缺失，LLM 基于产品类型和行业常识至少生成 3 条核心卖点
- **生成方式（强制）**：
  - Agent 必须用自身 AI 推理能力为每个产品独立生成卖点
  - 禁止编写 Python 脚本通过字符串模板/关键词匹配来批量生成
  - 每个卖点必须包含该产品的至少 1 个具体参数（如电池容量、LED 数量、尺寸等）
- **多样性红线（强制）**：
  - 同一批次中，任意卖点列（Q/S/U/R/T/V）的完全相同文本占比不得超过 10%
  - 违反此红线视为合规错误，必须返回重新生成
- AK 列：搜索关键词

## Rule 7: SPU/SKU 分组
- 同一系列产品（如 EMPBP29/EMPBP35/EMPBP41）归为一个 SPU
- 通过型号前缀字母匹配分组
- SPU 首行填写完整信息
- 后续 SKU 行的 A~AJ 列以及 BA~BB 列留空

## Rule 8: 主要市场
- B 列：主要市场1，默认填写 `Western Europe+UK+Australia`
- C 列：主要市场2，默认填写 `Eastern Europe+Russia`
- D 列：主要市场3，默认填写 `North America`

## Rule 9: 产品描述（SKU 维度）
- AN 列：中文产品描述
- AO 列：英文产品描述
- **关键约束**：AN/AO 属于 SKU 段信息，**每个 SKU 行都必须填写**
- 描述中的尺寸/克重必须取**该行 SKU 自身的值**，禁止将同一 SPU 下所有 SKU 的尺寸堆叠在一行
- **差异化强制要求**：不同产品的 AN/AO 描述**必须体现该产品的独特参数**。
  源文件 `_raw_desc` 中的关键信息（如灯珠数量、电池容量、控制方式、功率、充电时间等产品特有参数）
  必须提取并融入描述，**禁止所有产品共用同一模板描述**。若两个不同型号的产品 AN 内容完全相同，视为合规错误。
- **描述中禁止包含供应商型号/编号**（如 `编号：BH-HY-001` 或 `Model: BH-HY-001`）。型号应放在 AK 列，不属于产品描述。
- **描述结构强制要求**：
  - AN（中文）格式必须为：
    `尺寸：长*宽*高cm\n净重：XXg\n材质：材料名称`（如有额外信息依次换行追加，注意：必须全部是中文，不能有英文）
  - AO（英文）格式必须为：
    `Size: L*W*Hcm\nNet Weight: XXg\nMaterial: material name`（如有额外信息依次换行追加，注意：必须全部是英文，不能有中文）
  - **合规示例 (Good Case)**:
    - AN: `尺寸：直径7.2cm*高19.5cm\n净重：110g\n材质：ABS\n包装：邮购盒\n产品优势：12颗LED火焰灯珠，动态仿真火焰效果`
    - AO: `Size: Dia7.2cm x H19.5cm\nNet Weight: 110g\nMaterial: ABS\nPackage: Mail box\nAdvantages: 12 LED flame bulbs with dynamic flame effect`
  - **违规示例 (Bad Case)**:
    - `编号：BH-HY-001\n尺寸：Normal\n材质：ABS+PC`（包含型号编号，尺寸为占位符，缺少净重）
    - `Model: BH-HY-001\nSize: Normal\nMaterial: Product`（包含型号，Material 为占位符）

## Rule 10: 采购价格
- AW 列：采购价格（纯数字），源文件没有则留空
- AX 列：留空
- AY 列：货币单位（默认 USD），若 AW 为空则 AY 也留空
- **货币单位判断**：优先从源文件的表头/标注中识别实际货币单位（如 `RMB`、`EUR`、`GBP` 等），
  若源文件明确标注为人民币则 AY 填 `RMB`，未标注则默认 `USD`。**不可忽略源文件中的货币标注而盲目使用默认值。**

## Rule 11: 包装信息
- AP 列：包装方式，**使用标准简写**：
  - `BK` = 散装 (Bulk)
  - `CB` = 彩盒 (Color Box) / 彩盒装 / 彩贴
  - `WB` = 白盒 (White Box)
  - `PB` = 胶袋/塑料袋 (Polybag) / OPP袋 / PE袋
  - `BP` = 泡壳 (Blister Pack) / 插卡
  - `OTHER` = 其他
- **常见源文件描述到标准简写的映射**（Agent 必须在提取阶段识别）：
  - `彩盒` / `彩贴` / `color box` → `CB`
  - `邮购盒` / `mail box` / `白盒` / `white box` → `WB`
  - `OPP袋` / `OPP自封袋` / `PE袋` / `polybag` / `胶袋` → `PB`
  - `泡壳` / `吸塑` / `插卡` / `blister` → `BP`
  - `散装` / `bulk` → `BK`
  - 若源文件未描述包装方式，按 Rule 15 Fallback 处理
- AQ 列：**单个最小销售包装中含几个产品**。大多数情况为 `1`。当源文件描述"2个装"/"两个装"时，AQ 应填 2。**AQ 不是外箱数量，不要与 AR 混淆。**
- AR 列：**外箱装入数量**，必须优先从源文件提取（如 `48pcs`、`50套`），仅缺失时用 Rule 15 估算。
- AS 列：外箱毛重（KG），从源文件 `净重/毛重` 格式中取毛重值（如 `8.5/10kg` 取 `10`）
- AT/AU/AV 列：外箱长/宽/高（cm），从源文件提取（如 `520*520*560mm` 转换为 `52/52/56`）

## Rule 12: MOQ
- AZ 列：最小起订量

## Rule 13: 模版样式
- 读取模版第 3 行样式作为参考
- 所有新增行添加细边框
- 文本居中对齐、自动换行
- 行高统一为 80

## Rule 14: 环境清理
- 任务结束后删除 `temp/` 临时文件夹下的 JSON 和图片
- AM 列（尾缀）可为空

## Rule 15: 智能 Fallback（源文件信息缺失时）
- **优先使用源文件中的实际数据**，仅在确实缺失时才启用估算
- **Agent 必须先尝试从 `_raw_desc` 或已拆分的 `_raw_*` 字段中提取数据**，确认确实无法获取后才使用估算：
  - 检查 `_raw_packing` → 映射为 AP 标准简写
  - 检查 `_raw_qty_per_carton` → 填入 AR 列
  - 检查 `_raw_carton_gw` → 填入 AS 列
  - 检查 `_raw_carton_meas` → 拆分为 AT/AU/AV 列
- 当源文件确实缺少数据时，由 LLM 根据产品类型和常识估算：
  - **包装方式（AP）**：套装类产品默认 `CB`（彩盒），单品/小件默认 `PB`（胶袋）
  - **外箱数量（AR）**：根据单品体积估算，小件 36~96 个/箱，套装 8~24 个/箱
  - **外箱毛重（AS）**：公式 = `单品估算重量(kg) × 外箱数量 × 1.15`（1.15 为外箱自重系数）
  - **外箱尺寸（AT/AU/AV）**：根据产品类型选择常见箱规，如：
    - 厨具套装：55×38×35 cm
    - 小件工具：45×30×25 cm
    - 砧板类：55×40×35 cm
  - 尺寸（长/宽/高 cm）：根据产品类型和图片估算
  - 净重（g → KG）：根据材质和尺寸估算
- **重要约束**：即使是估算数据，最终输出的 JSON 也必须完整包含 `AQ`, `AR`, `AS`, `AT`, `AU`, `AV` 列字段，**绝不可省略这些列**。
- 所有估算值在 JSON 中建议通过 `_estimated` 辅助字段标记，提醒用户确认

## Rule 16: 数据合规性自动扫描 (Automated Compliance Check)
- 在生成 `target.json` 后且写入 Excel 前，**必须**运行 `scripts/check_compliance.py` 进行全量扫描。
- 扫描内容包括：
  - BCD 列是否匹配标准市场默认值 (Rule 8)
  - AP 列是否为标准简写且非空 (Rule 11)
  - P/R/T/V/X/Z/AB/AD/AF/AH/AJ/AO 等英文列是否含有中文字符 (Rule 4, 6, 9)
  - BB 列是否固定为 "Howstoday" (Rule 3)
  - O/P 列标题是否包含供应商型号或规格参数 (Rule 4)
  - Q/S/U 列卖点名称是否为通用占位符（如「亮点」「卖点一」） (Rule 6)
  - R/T/V 列卖点名称是否为通用占位符（如 "Point 1"） (Rule 6)
  - AN 列是否包含 `编号：` 前缀 (Rule 9)
  - AO 列是否包含 `Model:` 前缀 (Rule 9)
  - AP 列是否全部为 OTHER 的警告 (Rule 11)
  - AQ 列是否 > 10 的警告 (Rule 11)
  - AR 列是否全部相同的警告 (Rule 11)
  - AS/AT/AU/AV 列是否全部为空的警告 (Rule 15)
- **强制要求**：若扫描结果显示 `Errors > 0`，严禁执行写入脚本，必须返回上一步修正数据。
