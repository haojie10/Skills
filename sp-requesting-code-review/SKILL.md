# 请求代码审查

## 概述

分发一个代码审查子智能体（Code Reviewer Subagent），在问题级联之前捕捉它们。审查者获取精心准备的上下文进行评估——绝不是你会话的历史记录。这使审查者专注于工作成果，而不是你的思考过程，同时也保留了你继续工作的上下文。

**核心原则：** 尽早审查，频繁审查。

## 何时请求审查

**强制要求：**
- 在子智能体驱动开发（subagent-driven development）的每个任务之后
- 完成主要特性之后
- 在合并到 main 分支之前

**可选但有价值：**
- 卡住时（获取全新视角）
- 重构前（基线检查）
- 修复复杂 Bug 后

## 如何请求

**1. 获取 Git SHA:**
找到开始提交（`BASE_SHA`）和当前提交（`HEAD_SHA`）。

**2. 分发代码审查子智能体:**
准备好变更描述、计划或需求说明，以及 SHA 范围。

**3. 根据反馈采取行动:**
- 立即修复 Critical（关键）问题
- 在继续之前修复 Important（重要）问题
- 记录 Minor（次要）问题留待以后处理
- 如果审查者有误，提出反驳（附带推理）

## 红线规则

**绝不：**
- 因为“它很简单”而跳过审查
- 忽略关键问题
- 在未修复重要问题的情况下继续
- 与有效的技术反馈争论

**如果审查者有误：**
- 用技术推理进行反驳
- 展示证明其有效的代码/测试
- 请求澄清
