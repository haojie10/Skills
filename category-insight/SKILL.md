# Category Insight (品类深度洞察与渠道对比)

本技能用于针对特定零售市场（如北美、加拿大、欧洲、亚太等）和不同渠道（如 Dollarama、Dollar General、Target、Walmart、Costco、Amazon 等），对特定产品品类进行深度商业情报调研与横向对比，生成高颜值、交互式的自包含 HTML 报告，并自动上传发布至 GlobalTradeBuddy 平台。

## 完整执行流程与标准

### 0. 前置查重拦截（强制执行，避免重复生成）

在启动深度调研和概念图生成之前，**必须先检查平台是否已有该品类/渠道的情报研报**：
1. 运行查重脚本（或调用 API）：
   ```bash
   python bin/check_report.py --product "品类关键词" --region "目标国家"
   ```
2. **判断逻辑**：
   - **若已存在相关报告**：立即向用户汇报已有报告的标题、发布时间与查看链接，并询问：
     > *“平台报告大厅中已存在《[报告标题]》（查看链接：[url]）。请问您是直接查阅该报告，还是需要基于最新数据重新生成并覆盖更新？”*
     若用户指示仅需查阅，则直接结束，不再重复耗费 Token 和生图额度；若用户明确要求重新生成，则继续后续步骤。
   - **若不存在该报告**：直接进入第一步开始调研。

### 第一步：明确要素与检索

1. **锁定核心要素**：
   - **目标品类**：具体产品品类（如：泳帽 / 硅胶泳帽、手持风扇、牛皮纸袋、超细纤维抹布等）。
   - **目标区域与渠道**：目标国家/市场（如美国、加拿大、德国、全美连锁商超）及核心调研渠道（如 Dollarama vs Canadian Tire vs Walmart）。
2. **检索真实市场信息**：
   - 使用 `search_web` 收集该渠道中目标品类的在售商品、品牌分布、价格带、包装形式、规格参数与热销卖点。
   - 提取消费者的真实痛点（亚马逊差评、Reddit 讨论、专业测评网站等）。

### 第二步：结构化分析与内容构建

必须包含以下五大核心模块（严格遵循 [方法论](references/methodology.md)）：

1. **品类矩阵分析**：梳理各渠道的核心 SKU、价格区间、材质规格、主打功能。
2. **多渠道横向对比**：从定位、定价策略、包装视觉、目标客群四个维度进行深度对比。
3. **用户痛点与差评诊断**：提炼消费者抱怨最多的 Top 3~5 核心痛点。
4. **中国制造差距诊断**：从工业设计、材料应用、包装环保性、成本控制等维度剖析当前国产出海产品的痛点。
5. **反堆料研发升级建议**：
   - 提供 2~3 个具体的产品升级提案（每款提案需覆盖：适用人群画像、解决的具体痛点、反堆料降本/差异化工程设计）。

### 第三步：视觉化与 HTML 报告生成

1. **UI 规范**：严格遵循暖沙极简设计规范（暖白背景 `#fdfbf7`、主卡片 `#f6f3ec`、强调色 `#ff641e`、无 Emoji、系统无衬线字体）。
2. **元数据标签**：在 HTML `<head>` 中必须注入标准 `<meta>` 标签：
   - `<meta name="category" content="product">`
   - `<meta name="summary" content="...">`
   - `<meta name="products" content="...">`（品类名必须对齐 GTB 54 标准行业分类）
   - `<meta name="regions" content="...">`
   - `<meta name="channels" content="...">`
3. **自包含嵌入**：报告中的所有配图和概念设计图必须使用 Base64 编码内嵌至单个 HTML 文件中。可运行 `scripts/embed_images.py` 自动完成压缩与嵌入。

### 第四步：自动发布与上传至平台

报告生成并通过本地自检后，必须调用发布脚本推送至平台：

```bash
python C:/Users/066/.gemini/config/skills/category-insight/scripts/publish_report.py <path_to_html>
```

## 质量要求

- **命名规范**：最终报告文件必须以 `品类-市场-insight.html`（短横线命名）命名。
- **完整性**：必须包含品类矩阵、差异对比、痛点分析、差距诊断以及研发建议五大结构。
- **整洁度**：确认工作目录已清除临时图片，仅保留最终的自包含 HTML 报告。
- **自动化上线**：必须确保报告已通过 `publish_report.py` 成功推送至 `https://marketgraphic.cn` 平台并反馈 Report ID。
