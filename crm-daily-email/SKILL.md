# CRM 每日邮件提取

从 CRM 系统的"每日邮件"预设查询中批量提取邮件内容，按客户维度生成深度业务总结。

## 约束

- CRM 地址：`http://192.168.0.36`
- 无 API，仅浏览器操作
- **默认用户已登录**，无需执行登录流程
- 邮件正文采用全量提取（不截断）
- 仅处理"预设查询 → 每日邮件"
- 每个客户/收件人必须独立列出，禁止合并

## 执行流程

### 阶段 1：导航至"每日邮件"并设置 200 封/页

1. 导航至 `http://192.168.0.36/#/email`
2. 等待页面加载完成
3. 在左侧面板底部找到并点击 **"预设查询"** 标签页
4. 在预设查询列表中找到 **"每日邮件"** 并点击（位置不固定，需通过文本匹配定位）
5. 等待邮件列表加载
6. **关键步骤：设置每页显示 200 封**
   - 找到页面底部的分页组件（`.el-pagination`）
   - 点击"每页条数"下拉框，选择 **200 条/页**
   - 等待列表重新加载完毕
7. 读取 DOM 获取总邮件数

### 阶段 2：提取邮件列表元数据（可选快速预览）

在正文提取前，可先通过一次性 JS 注入获取列表概览：

```javascript
// 快速获取所有行的摘要信息
const rows = document.querySelectorAll('.el-table__row');
const meta = Array.from(rows).map((r, i) => ({
  index: i,
  text: r.innerText.replace(/\n/g, ' | ')
}));
console.log(JSON.stringify(meta));
```

### 阶段 3：键盘流逐封提取正文（核心）

采用 **"点击首封 → 键盘下键循环"** 模式，这是最稳定、最高效的方案。

```
执行步骤：
  1. 点击列表中的第一封邮件（第一行 .el-table__row）
  2. 等待右侧详情面板加载（约 1 秒）
  3. 读取正文：document.querySelector('.emailDetailBox main').innerText
  4. 记录当前邮件的 主题 / 发件人 / 时间 / 正文
  5. 按下键盘 ↓（Down Arrow）切换到下一封邮件
  6. 等待详情面板更新（约 0.8-1 秒）
  7. 重复步骤 3-6，直至读完所有邮件（最多 200 封）
```

#### 技术要点

- **为什么用键盘下键？** 避免了逐行计算像素坐标的不稳定性，也避免了滚动后坐标偏移的问题。键盘下键会自动选中下一行并触发详情面板更新。
- **等待策略**: 每次按下键后等待 0.8-1 秒，确保 `.emailDetailBox main` 容器内容已刷新。
- **全量抓取**: 对于包含费用表格、历史引用的长邮件，`innerText` 会一次性返回所有内容，无需滚动。
- **批次拆分**: 每个 browser_subagent 处理约 20-30 封邮件。适当分批避免单次上下文过长。

#### 退化方案

如果键盘下键无法正常切换（极少见），退化为逐行点击：
- 向下滚动列表
- 根据 `.el-table__row` 的 DOM 顺序依次点击

### 阶段 4：深度业务总结

1. **合并数据**: 整合所有邮件的元数据与全量正文。
2. **语义分组**: 按 **客户 (Customer)** 或 **项目 (Project)** 维度进行分组。
3. **执行深度分析**: 对每一组邮件，按照 `assets/deep_analysis_template.md` 模板进行结构化解析：

   对每个客户/项目生成以下内容：
   
   #### 1. 业务背景 (Context)
   - 关联单据：PO#, B/L#, Item#, 进仓编号
   - 事件说明：邮件起因（如"货代发送费用对账单"）

   #### 2. 核心更新 (Key Updates)
   - 数据明细：费用/体积/金额变化、ETD/ETA 更新
   - 重要变更：明确哪些信息发生了变化

   #### 3. 待办动作 (Action Required)
   - 用户需要执行的操作（确认/回复/准备附件）
   - 建议的回复话术

   #### 4. 风险预警 (Risk & Deadline)
   - 截止日期
   - 逾期后果（如"不回复视为默认无误"）

4. **输出**: 保存为 `{日期}_每日邮件深度业务总结.md`

## DOM 选择器参考

- **邮件页签**: 文本匹配 "邮件"
- **邮件行**: `.el-table__row`
- **正文面板容器**: `.emailDetailBox main`（核心！承载全量历史内容）
- **翻页**: `.el-pagination .btn-next`
- **每页条数选择器**: `.el-pagination` 中的下拉组件
- **预设查询标签**: 文本匹配 "预设查询"
- **每日邮件条目**: 文本匹配 "每日邮件"

## 重要注意事项

- **不要点击** 侧边栏人名下的子项（如"未归类"、"合作客户"等），只点人名
- 如果误点导致展开子菜单，再次点击人名可以收起
- "每日邮件"按钮位置不固定，必须通过文本内容定位
- 每个收件人/客户独立列出，**禁止合并多个客户为一组**
- 键盘下键切换后，务必等待详情面板内容刷新再提取
- 系统通知类邮件（如"垃圾邮件拦截通知"、"反垃圾通知"）可标记为低优先级或跳过
