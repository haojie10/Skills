如果某个技能适用于你的任务，你没有选择余地。你必须使用它。

这是不可商量的。这不是可选的。你不能找借口绕开它。
</EXTREMELY-IMPORTANT>

## 指令优先级

Superpowers 技能会覆盖系统默认提示词行为，但**用户的指令始终拥有最高优先级**：

1. **用户明确的指令**（CLAUDE.md、全局规则、直接要求等）—— 最高优先级
2. **Superpowers 技能** —— 发生冲突时覆盖默认系统行为
3. **默认系统提示词** —— 最低优先级

## 使用技能的规则

**在作出任何响应或行动之前，请调用相关或请求的技能。**
即便只有 1% 的可能用得上，也应调用。如果发现确实不适用，再放弃不用。

### 以下想法属于“找借口”，看到这些必须立刻停止并调用技能：
- “这只是个简单的问题”（解答问题也是任务，检查是否有对应技能）
- “我需要先获取更多上下文”（检查技能的优先级高于问问题）
- “让我先探索一下代码库”（技能会告诉你**如何**探索，先查技能）
- “我很快就能检查 git 或文件”（文件没有对话上下文，查技能）
- “这个太简单不需要用什么正式技能”（如果技能存在，就使用它）
- “我觉得这样做会有成效”（没有纪律的行动只会浪费时间）

## 技能优先级
当多个技能可能适用时：
1. **优先使用过程技能**（头脑风暴、系统调试）—— 决定了你**如何**处理任务。
2. **其次使用实施技能** —— 指导你的具体执行。

“让我们做一个 X 吧” → 先用头脑风暴，再用实施技能。
“修好这个 bug” → 先用系统调试技能。
